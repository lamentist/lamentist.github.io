소개

컴퓨터공학을 전공하고 개발자로 커리어를 시작해, 가상화폐 자동거래 시스템의 거래소 API 연동과 라이브러리 구축을 담당했습니다. 이후 물류 현장에서 재고 수불 업무를 맡으며 반복되는 수작업을 직접 자동화했고, 그 결과물이 실무에 정착되면서 IT운영개발팀으로 이동해 사내 시스템 개발과 업무 자동화를 담당하고 있습니다.

현장 업무를 직접 해 본 덕분에 무엇을 만들어야 하는지 정의하는 일에 강점이 있습니다. 포장 이력 관리 체계 도입으로 CS 대응 시간을 95% 줄였고, 수기 장부 처리와 증빙 대사 검증 등 반복 업무를 자동화했습니다. 한 번 해결한 문제는 매뉴얼로 남겨 다른 사람도 처리할 수 있게 만드는 편입니다.

01

사례 1 · 유통관리팀 재직 중 요청 대응, 1인 개발

카카오톡 주문 자동 수집

지점별 오픈채팅방에 실시간으로 올라오는 주문을 자동으로 읽어 주문서로 정리, 하루 종일 대응하던 업무를 마감 전후 30분 작업으로 단축

웹 시연 열어 보기 ↗ 샘플 대화로 브라우저에서 직접 동작합니다.

문제

  • 고객 주문이 지점별 카카오톡 오픈채팅방에 실시간으로 올라옴
  • 담당자가 하루 종일 대화를 지켜보며 주문서에 수기 입력
  • 취소·수정 메시지가 섞여 누락과 중복 위험

접근

  • 프로그램이 카카오톡 PC 창에서 10초마다 저장(Ctrl+S)을 자동으로 실행해 대화를 텍스트로 확보
  • 주문 규칙(상품명 뒤 수량)과 취소 규칙("취소요", "1취소요") 정리
  • '취소'가 들어간 메시지는 같은 작성자의 직전 주문을 찾아 그 수량만큼 차감하고, 원래 주문 행은 주황색으로 표시
  • 애매한 메시지는 임의 판단하지 않고 회색으로 표시해 사람이 확인
  • 구글 시트와 엑셀에 기록, 수령일별 시트로 자동 분리

성과

  • 하루 종일 실시간 대응 → 주문 마감 전후 30분 작업
  • 이전 실행 기록을 따로 저장하지 않고 매번 전체 대화를 처음부터 다시 읽어 계산하므로, 프로그램을 재시작해도 같은 결과
  • 설치 파일로 배포해 다른 PC에서도 사용

사례 2 · IT운영개발팀 전환 후 타 부서 요청 대응, 1인 개발

판매처 주문 자동 수집 (주문 크롤러)

API가 없는 판매처 여러 곳의 주문을 자동 로그인과 인증으로 받아 사내 양식으로 가공, 하루 3회 약 1시간의 수작업을 5분 내외로 단축

문제

  • 판매처마다 사이트에서 주문 엑셀을 내려받아 사내 양식으로 손수 가공
  • 판매처 4곳을 각각 약 5분씩 처리, 하루 3회 반복해 총 1시간가량의 작업(건당 5분은 짧게 잡은 값)
  • 일부 판매처는 2차 인증(이메일·휴대폰)이 있어 자동화가 어려움

접근

  • 크롬 제어로 로그인부터 다운로드, 가공까지 한 번에 실행
  • 이메일 인증은 메일함(IMAP)에서 인증번호를 자동으로 읽고, 못 찾으면 수동 입력으로 전환
  • 판매처마다 달라지는 부분만 클래스로 분리해, 새 판매처는 템플릿을 채워 추가
  • 테스트 모드: 주문 상태를 바꾸는 단계는 건너뛰고 로그인과 진입까지 확인

성과

  • 하루 3회 총 1시간(4곳 × 5분 × 3회) → 5분 내외. 엑셀을 열어 특이사항을 찾는 시간까지 넣으면 실제 절감은 더 큼
  • 체크한 판매처를 한 번에 실행하고, 부하 방지를 위해 동시 처리는 3개로 제한(초과분은 대기 후 순차 투입)
  • 우편번호·연락처 누락 건은 파일명 변경과 배경색 하이라이트로 표시
  • 자동 업데이트와 사용 매뉴얼을 갖춰 담당자가 직접 운영

사례 3 · 물류 현장 개선, 사내 ERP 연동

검수 포장대 스캔 시스템

포장 단계의 송장 스캔 기록을 시트와 사내 시스템에 자동으로 남겨, 오출고 문의 시 포장 영상 확인 시간을 1시간에서 3~20분으로 단축

문제

  • 오출고 CS가 들어오면 포장 영상을 확인해야 원인을 알 수 있음
  • 언제 어느 포장대에서 포장했는지 기록이 없어 CCTV를 넓은 시간대에 걸쳐 확인해야 해서 건당 약 1시간 소요

접근

  • 포장대마다 바코드 리더기를 연결해 송장을 스캔할 때 스캔 위치, 스캔 시간, 송장번호를 기록
  • 스캐너를 기본 HID(키보드 입력) 방식 대신 USB COM 포트 모드로 설정, 프로그램이 포트별로 직접 수신해 포장대 식별 (HID 방식은 스캐너 구분 불가)
  • 구글 시트와 사내 ERP(API)에 자동 업로드
  • 포장대·COM 포트 설정을 JSON 텍스트 파일로 분리, 수정 후 프로그램 재실행만으로 포장대 추가
  • 연결 끊김은 재시도 루프와 오류 로그로 대응

성과

  • 오출고 CS 확인 시간 1시간 → 3~20분 (최대 95% 단축): 송장번호로 스캔 시간과 포장대를 찾아, 그 시간의 해당 포장대 CCTV만 보면 확인 끝
  • 월 평균 약 15,000건(영업일 20일 기준 하루 약 750건)의 스캔을 안정적으로 기록
  • 현재는 사내 ERP로 일원화되어 '스캔송장목록' 화면에서 스캔 시간·송장번호·포장 위치를 조회하고 엑셀로 내려받을 수 있게 개선

사례 4 · 구매·발주 업무 지원, 구글 시트와 Apps Script

지점별 거래명세서 자동 생성

발주 시트에 수량만 입력하고 메뉴를 누르면 지점별 거래명세서와 전 지점 합계 명세서가 자동으로 만들어지도록 구현, 열·지점·품목이 바뀌어도 코드를 고치지 않는 구조

문제

  • 지점별 발주 수량을 보고 명세서 양식에 품목, 규격, 수량, 단가, 합계를 하나씩 옮겨 적음
  • 지점 수만큼 반복되고, 품목이나 지점이 바뀔 때마다 양식을 손봐야 함

접근

  • 사용자는 메뉴 선택만으로 실행. 발주 시트의 수량과 단가를 읽어 지점마다 양식 시트를 복제해 자동으로 채우고, 수량이 1 이상인 품목만 표시
  • 열 위치를 고정하지 않고 머리글 이름(품목명, 포장단위, 가격 등)으로 찾아, 열이나 지점을 추가해도 코드 수정이 필요 없음
  • 품목이 양식 기본 행 수를 넘으면 행과 서식, 수식을 자동으로 늘리고, 전 지점 합계 명세서도 함께 생성
  • 동시 실행을 막고, 머리글을 못 찾으면 원인을 알려 주는 오류 메시지를 표시
  • 사용설명서 시트도 코드로 자동 생성해 담당자가 직접 사용할 수 있게 인수인계

성과

  • 지점별 수기 작성 → 메뉴 한 번으로 전체 지점 명세서 생성
  • 작업자의 엑셀 숙련도에 따라 달랐던 작업(숙련자 30분 이내, 비숙련자는 최대 2시간으로 추정, 실측값 아님)을 누가 하든 클릭 한 번으로 끝나는 작업으로 표준화
  • 지점·품목이 바뀌어도 코드 수정 없이 운영
  • 단가표 연동(참고 열 방식)은 구현해 두었으나 현재는 보류

일하는 방식

네 사례에 공통으로 쓴 방법

  1. 1

    현장 확인

    누가 어디서 무엇을 반복하는지 직접 보고 듣습니다

  2. 2

    규칙 정리

    예외와 판단 기준을 말로 먼저 정리합니다

  3. 3

    직접 구현

    작게 만들어 현장에서 바로 써 보게 합니다

  4. 4

    효과 확인

    전후 시간을 재고 수치로 남깁니다

  5. 5

    운영 인수

    매뉴얼과 자동 업데이트로 담당자가 직접 운영합니다
